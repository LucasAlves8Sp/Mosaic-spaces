# AGENTS.md -- instructions for an agent or reviewer entering this repository

## What this repository is

A Lean 4 formalization of the article `article/mosaic_article.tex` ("Mosaic spaces generated by
continua and by Peano continua", Lucas Alves de Almeida). Everything except the examples is
formalized; the examples (Section 3 and the Appendix, van Douwen's space in Section 5, Example 7.3
and the Theorem 7.4 strictness claims that use them) were excluded at the author's request.

- 70 statements are Comparator-checked (unsandboxed so far).
- Q3 is answered as asked by `G`; Q2 (Corollary 6.4 in full), Q1a and Q1b by the cone over `G`.

Read `CHECKPOINT.md` first: it says what exists, what has been checked, and what is missing. It is
not registered by Palomar.

## Ground rules (from the author's brief)

1. No `sorry`, `admit`, `sorryAx`, `native_decide`, custom `axiom`, `unsafe`, `opaque` constants
   or elaborator tricks in `Solution.lean` or under `MosaicSpaces/`. The only permitted holes are
   one `sorry` per compared statement in `Challenge.lean` (author's decision, 2026-11-16).
2. Permitted axioms for every advertised theorem: `propext`, `Quot.sound`, `Classical.choice`.
3. Do not assume mosaic spaces are Hausdorff, first countable or metrizable. Do not replace
   "locally arcwise connected" by "locally path connected", or "metric continuum" by a convenient
   surrogate, without recording the change in the ledger.
4. Counterexamples are constructed, never assumed. A theorem that takes the continuum `K`, the set
   `Z`, or van Douwen's theorem as a hypothesis is conditional and must be labelled so; it may not
   be advertised as an answer to Q1/Q2/Q3 or as Theorem 7.4.
5. Never write "passed" for a check that did not run. Statuses to keep apart: *Lean build passed*,
   *Comparator passed*, *independent kernel checks passed*, *locally prepared for submission*,
   *registered by Palomar*.
6. Every `.lean` file starts with `module`, has at most 10,000 lines; `Challenge.lean` at most
   1,000 lines / 100 KiB and imports only Mathlib.

## Development loop

Linux or macOS with elan:

```
lake exe cache get
lake build                      # default targets: MosaicSpaces, Solution
lake build Challenge
lake env lean MosaicSpaces/X.lean   # check one file without writing .olean files
python3 scripts/check_sources.py .
```

Windows (the author's machine): `watch.ps1` is a request-file watcher left from the preparation
session (format documented at its top); it was not used to build this state.

After changing Lean sources: update the `status` and `lean` fields in `ledger/build_ledger.py`,
run it, and update `CHECKPOINT.md`.

## Suggested order of work

See `CHECKPOINT.md`, section "Remaining work". All non-example results are done. When you add a
compared statement:

1. Add it to `Challenge.lean` with `sorry`, copying any new definition verbatim from the library.
   Do not copy definitions whose bodies contain tactic proofs (e.g. `Fan.spine`): their proof
   terms can differ between the two environments; state the result without them instead.
2. Prove it under the same name in `Solution.lean`.
3. Add its name to `comparator.json` and to `scripts/axioms.lean`.
4. Update `ledger/build_ledger.py` (the `UPD` table) and `formalization.yaml` (`alignment`).
5. Rerun `scripts/verify_all.sh`.

## Review checklist for an independent reviewer

Take a clean checkout and the article only. For each ledger row marked `compared`, `proved` or `partial`: read the Lean
statement against the article lines cited; check quantifiers, hypotheses, subspace topologies and
nonvacuity; rebuild; run `#print axioms`. Do not rely on this file, the checkpoint or the report for
the result of any check: rerun it.
